# Сигнал — Flutter Web

Гражданская часть «Сигнала» написана на Dart с Flutter. Здесь находятся стена
обращений, двухшаговая анкета, тема обращения, фотографии и карта территорий.
Администраторы продолжают работать с обращениями через существующий интерфейс «Метки».

Используется Flutter **3.47.9**. [Официальная установка](https://docs.flutter.dev/install/manual).

```sh
flutter pub get
flutter analyze
flutter test
node --test test/browser/*.test.cjs
python3 tool/build.py
```

Готовая страница находится в `build/web`. Сервер должен отдавать её на одном
домене с `/api/public/appeals`, `/a/<номер>` и `/version.json`. Ключ Яндекс.Карт,
список городов и территории берутся из существующего публичного API. Шрифты Inter и Roboto
и движок CanvasKit входят в сборку и загружаются с того же сервера.

После сборки локальный просмотр запускается так:

```sh
python3 tool/serve.py --api http://127.0.0.1:8001
```

Страница открывается на `http://127.0.0.1:5181`, запросы направляются на указанный
локальный API. На этой машине работает настоящий FastAPI и отдельная локальная
PostGIS-база: новые обращения и фотографии сохраняются, появляются на стене
и остаются после перезапуска. В рабочую базу они не отправляются.

Для первого локального запуска из корня репозитория:

```sh
backend/.venv/bin/python signal_flutter/tool/local_backend.py setup --catalog /path/to/catalog.json --wall /path/to/wall.json --media-base http://127.0.0.1:5181
backend/.venv/bin/python signal_flutter/tool/local_backend.py serve --port 8001
```

Первичная настройка использует сохранённый публичный каталог одной организации
и, необязательно, копию её ленты. Если импортируются фотографии существующей
ленты, `--media-base` должен указывать на локальный сервер, который их отдаёт.
Скрипт создаёт контейнер `signal-flutter-local-db` с портом только на loopback,
применяет штатные миграции и сохраняет настройки в исключённой из Git и Docker
папке `.local`. Для повторного запуска данные импортировать заново не нужно;
достаточно запустить контейнер и команду `serve`. Клиентский сервер запускается
отдельно указанной выше командой `tool/serve.py`.

Сервис `appeals-web` в корневом Compose собирает эту версию через отдельный
Dockerfile. Перед первым запуском новой версии API нужна штатная миграция `0046`,
которая добавляет тему обращения. На рабочий сервер изменения автоматически не
выкатываются.

Черновики совместимы с прежней браузерной версией: используется тот же IndexedDB,
фотографии сохраняются как Blob, срок хранения — 24 часа. При неопределённом
результате отправки сохраняются токен и исходные данные: повторная попытка сначала
проверяет квитанцию и не создаёт второе обращение.

Сейчас целевая платформа — браузер. Файловый выбор, IndexedDB и Яндекс.Карты
подключены через небольшой браузерный адаптер в `web/signal_browser.js`; весь
интерфейс и логика обращения находятся в Dart. Android и iOS проекты не создавались.

При ширине окна от 960 px включается макет ПК: верхняя навигация, стена в две
колонки и отдельные двухколоночные шаги анкеты. На телефоне остаётся компактная
версия с нижней навигацией. Оба макета используют один контроллер и черновик;
изменение размера окна сохраняет выбранную территорию, текст и фотографии.
В анкете ПК фотографии можно выбрать кнопкой или перетащить в область добавления;
ограничения количества, форматов и размера одинаковы для обоих способов.
