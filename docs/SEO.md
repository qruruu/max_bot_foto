# SEO «Сигнала»

Действующая сборка: Flutter Web, `signal_flutter/Dockerfile`, сервис `appeals-web`.
Основной адрес: https://metka-signal.yunorit.ru/.

Настроены:

- Title: «Сигнал — обращения жителей Нефтеюганска».
- Description: «Сигнал — обращения жителей Нефтеюганска о городских проблемах:
  уборка и содержание территорий. Укажите место, сделайте фото и следите за
  ответом организации.»
- Canonical и og:url: основной HTTPS-адрес, без параметров.
- Open Graph: название, описание, тип website, локаль ru_RU.
- Twitter: summary, название и описание.
- Robots meta: index, follow, max-image-preview:large.
- robots.txt: обход сайта и ресурсов разрешён, обход API ограничен,
  указан абсолютный адрес карты сайта.
- sitemap.xml: основная страница и до 49 999 последних публичных карточек обращений.
- MaterialApp.title согласован с HTML, чтобы Flutter не заменял название вкладки
  после загрузки.
- Nginx отдаёт robots.txt как файл, а sitemap.xml направляет в appeals-api.
  Карта формируется из текущего состояния публикации, без кеширования приватных данных.

Оформление, основной интерфейс, форма и стена не менялись. Отдельные
страницы-витрины и незавершённое окно «О сервисе» из предыдущей попытки убраны.
React-клиент и «Метка» не изменены.

Публичные карточки `/a/<id>` уже имеют серверный HTML, индивидуальные title,
description, canonical и превью. Их существующие правила публикации и доступа
сохранены; приватные обращения не добавлялись в sitemap.

## Проверка и установка

Проверены исходный HTML, уникальность метаданных, canonical, XML карты сайта,
согласованность названий и неизменность тела HTML относительно исходного сайта.
Полная Flutter-сборка локально не запускалась: SDK отсутствует. Действующий
домен из этой среды не загрузился; live-верификация не выполнена.

На сервере с существующей конфигурацией из корня проекта:

```sh
docker compose --profile appeals up -d --build appeals-web
```

После установки проверить исходный HTML главной, /robots.txt, /sitemap.xml,
название вкладки после загрузки Flutter и работу стены/формы. API и база
не меняются, миграции не нужны.

## Подтверждение поисковых систем

В HTML главной страницы заданы метатеги google-site-verification и
yandex-verification, выданные аккаунтами владельца. Не удалять их после
подтверждения владения: поисковые системы могут проверять их повторно.
Метатеги являются публичными кодами подтверждения, а не паролями.

Google Search Console: право собственности подтверждено, sitemap.xml отправлен
17 ноября 2026. Ресурс: https://metka-signal.yunorit.ru/.

Яндекс Вебмастер: выбран способ «Метатег», код добавлен в исходный HTML.
После установки обновления нажать «Подтвердить» и отправить карту сайта
https://metka-signal.yunorit.ru/sitemap.xml. Кнопка подтверждения также означает
принятие пользовательского соглашения Яндекс Вебмастера; этот шаг выполняется
после согласия владельца.

## Улучшение обнаружения — 20 ноября 2026

- Добавлена микроразметка WebSite с названием «Сигнал», альтернативным именем
  «Сигнал Нефтеюганск», основным адресом и языком. Это подсказка о названии сайта,
  а не гарантия позиции в выдаче. Microdata работает без inline-JavaScript
  и без ослабления CSP.
- robots.txt разрешает GET-ресурсы публичного каталога и стены, включая фотографии.
  Ранее общий Disallow: /api/ запрещал их обход. Остальные API остаются запрещены
  роботам; авторизация и правила публикации не меняются.
- Динамическая карта сайта использует те же public_conditions, что публичная стена:
  только опубликованные обращения активных организаций, без спама и обращений
  проверяющих. После снятия публикации URL исчезает из карты. Карта содержит
  только адреса, без контактов, внутренних заметок и содержимого фотографий.
- Заголовок публичной карточки содержит город вместе с темой и номером обращения.
- Внешний вид Flutter-приложения не меняется.

Обновлять нужно appeals-api и appeals-web одной версией. Миграций нет.
Сначала собрать оба компонента, затем запустить API перед веб-контейнером:

```sh
docker compose --profile appeals build appeals-api appeals-web
docker compose --profile appeals up -d --no-deps appeals-api
docker compose --profile appeals up -d --no-deps appeals-web
```

Для проверки использована отдельная временная PostGIS-база. Тесты подтверждают,
что приватные/спам-обращения и обращения приостановленных организаций не попадают
в sitemap, а снятие публикации убирает URL без задержки кеша.
