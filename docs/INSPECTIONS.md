# Проверяющие администрации

При включённых организациях (`ORGANIZATIONS_ENABLED=true`) в кабинете владельца
есть отдельный модуль «Проверяющие». Владелец создаёт администрацию, затем аккаунты
её проверяющих. Вход общий, по прежнему адресу сервиса; проверяющему автоматически
открывается кабинет `/inspection`.

Аккаунты проверяющих, сеансы, доступы и переписки хранятся в общей базе отдельно от
пользователей организаций. Сессия проверяющего не позволяет открыть API операторов,
изменять фотографии или пользоваться кабинетом владельца.

## Доступ к организации

Администратор организации открывает «Проверяющие → Создать QR организации».
Владелец также может выпустить QR в своём модуле проверяющих. Код можно показать
на экране, скачать или передать его ссылку. Проверяющий сканирует его камерой,
выбирает изображение QR либо открывает ссылку и входит в свой аккаунт.

QR действует 15 минут. Создание нового кода отменяет прежний неиспользованный.
Успешное использование погашает код для всех аккаунтов, включая использовавший его.
Одновременные запросы обрабатываются с блокировкой записи в PostgreSQL: выиграет один.
Секрет хранится только в виде SHA-256; ссылка передаёт его во фрагменте, который
клиент убирает из адресной строки. Выдача и получение доступа записываются в журнал
без самого секрета.

Доступ принадлежит конкретному аккаунту, а не всей администрации. У каждого сотрудника
свои QR для каждой организации. После получения доступа организация остаётся в его
списке до отзыва владельцем. Для восстановления отозванного доступа нужен новый код.
Приостановленная организация недоступна проверяющим.

## Фотографии, отчёты, обращения

В кабинете проверяющего фотографии разделены по организациям. Доступны только рабочие
фотографии (`production`), подтверждённые при закрытии дня в Метке. Используется
тот же снимок содержимого `DayPhotoReview`, что и при проверке дней. До закрытия дня
список, карточка, превью, отчёт и Excel не раскрывают снимок. Поздняя фотография требует
подтверждения при следующем закрытии. Изменённый после закрытия снимок скрывается до
повторного подтверждения. Смена режима приёма организации не открывает тестовые фото.

Есть фильтры периода, микрорайона, вида работы и дефекта, отчёты по микрорайонам и работам,
Excel, обращения граждан с фотографиями и названием организации. Для изображений
обращений проверяется и организация обращения, и принадлежность фото обращению.
Изменять обращения проверяющий не может. Контакты жителей и внутренние заметки
организации в кабинет проверяющего не передаются.

API использует отдельный разрешённый набор полей. В карточках, справочниках и Excel нет
списка и названий чатов MAX, отправителей, операторов, истории разметки, её источника,
уверенности/ответов нейросети, OCR, служебных имён файлов и путей Диска. Эти поля также
нельзя использовать как скрытые фильтры. Исходные данные организаций сохраняются.

Разделы кабинета находятся в левой панели, как у операторов. Панель сворачивается;
проверяющий может сохранить собственный порядок разделов. Архив использует таблицу операторского интерфейса:
превью и номер снимка, дата/время и время получения, микрорайон, координаты, вид работы,
отметка неисправности и статус. Доступны быстрые периоды, сортировка по съёмке или
получению, поиск по номеру, описание видов работ и просмотр оригинала через защищённый
API без раскрытия пути файла. Служебные колонки операторов при этом не передаются.

«Карта фотографий» показывает миниатюры и группы снимков с теми же фильтрами и без
ограничения страницы архива. Все части загружаются по курсору с исходным верхним ID.
На карту, в счётчики и уведомления попадают только подтверждённые фотографии; правки
после закрытия скрывают их до повторного подтверждения. «Микрорайоны» показывает
границы и список территорий. Рисование, перемещение вершин и сохранение недоступны.
Для обеих карт используется существующий ключ `YANDEX_MAPS_API_KEY`, как у операторов.

В отчёте доступны сводки, таблица «Вид работы × микрорайон», переходы по числам к
фотографиям и Excel с теми же ограничениями. Обращения используют тот же интерфейс
списка и карточки, что и у администрации организации: фильтр состояния, фотографии,
время съёмки, координаты и оригинальные кадры. Изменение состояния и внутренние
заметки проверяющим недоступны.

Кнопка «Обновить» перечитывает текущую выборку. Карточка фотографии открывается поверх
списка; закрытие кнопкой, Escape или возвратом браузера сохраняет страницу, фильтры,
прокрутку и фокус. Кнопки перехода работают по всей текущей выборке фотографий.

## Аккаунты и чаты

Проверяющие, чьи аккаунты создал владелец, могут создавать сотрудников своей
администрации. Сотрудники не могут создавать новые аккаунты и не наследуют доступы
создателя. Все активные проверяющие одной администрации могут общаться лично.

После получения доступа к организации в контактах появляются только её активные
администраторы. Операторы и служебный аккаунт владельца организации не показываются.
Администратор отвечает в разделе «Проверяющие» своей организации. Переписка отдельная
для каждой пары участников; третьи проверяющие и другие администрации её не видят.
При отзыве доступа чат с администраторами становится недоступным. Повторная отправка
с тем же `client_id` не создаёт дубль; есть счётчики непрочитанных, отметки прочтения,
обновление и загрузка предыдущих сообщений. Чаты используют общий с операторами
интерфейс: поиск по имени и организации, аватары, даты, мобильный переход между
списком и диалогом, Enter для отправки и Shift + Enter для новой строки. Черновики
сохраняются отдельно для каждого собеседника в открытом модуле; загрузка истории
сохраняет положение прокрутки. Новые сообщения подгружаются по курсору без пропусков
при поступлении большой пачки. Счётчик в боковом меню учитывает только доступных
собеседников; аватары повторно проверяют права при каждом запросе.

Владелец видит все аккаунты администрации, может изменить имя, сбросить пароль,
приостановить аккаунт или всю администрацию, отозвать доступ к отдельной организации
и просмотреть переписки. Приостановка и сброс пароля завершают действующие сеансы.
Повторное включение администрации не восстанавливает ранее завершённые сеансы.

## Личные настройки

Настройки открываются через профиль внизу левой панели и используют общие с оператором
компоненты: профиль с аватаркой, оформление, уведомления на экране и звук, безопасность
со сменой пароля, активные сеансы и их завершение. Изменения относятся только к своему
аккаунту проверяющего. Смена пароля завершает все его сеансы; завершить чужой сеанс
или получить аватарку другого аккаунта через эти API нельзя. Данные устройств и время
активности хранятся отдельно от сеансов организаций. Уведомления относятся к фотографиям,
ставшим доступными после закрытия дня выбранной организации.

## Обновление

Нужны обновлённые API и интерфейс и штатные миграции **0037–0038** через контейнер `migrate`.
Они добавляют таблицы проверяющих и поля личного профиля/сеансов, не меняя роли операторов, фотографии, закрытые дни
или существующие доступы организаций. Общая команда миграции обновляет и базы
организаций. Камера сканирования требует HTTPS (или localhost) и разрешения браузера;
при недоступной камере остаются сканирование изображения и ссылка приглашения.
