# Распознавание штампов камеры

По умолчанию используется PaddleOCR PP-OCRv5 mobile через RapidOCR 3.10.0 и ONNX Runtime
на CPU. Детектор — `ch_PP-OCRv5_det_mobile`, распознаватель —
`eslav_PP-OCRv5_rec_mobile` (русский, английский, цифры). Tesseract `rus+eng` остаётся
резервным распознавателем. Классификатор 16 видов работ и его обучение не менялись.

## Выбор модели

Проверка 14.10.2026: пять присланных фотографий и отдельный фрагмент даты. Скриншоты
обрезаны до самой фотографии, без полей операторской формы. Последний снимок 960×1280
используется целиком. Это небольшая проверочная выборка, а не оценка точности на всех
будущих фотографиях.

Сравнивались Tesseract 5, EasyOCR 1.7.2 (`ru,en`, CPU) и PP-OCRv5 mobile
(`eslav`, CPU). EasyOCR дополнительно проверялся на нижней части кадра; он несколько
раз подменял цифру `3` буквой `З`, а двоеточия времени — точками. PP-OCRv5 сохранял
цифры и разделители на этих примерах. Его пропущенные пробелы и разделение одной
строки на несколько блоков обрабатываются отдельно, без подмены цифр.

Повторяемый замер выполняется скриптом `backend/scripts/benchmark_ocr.py`: один движок
на отдельный процесс/контейнер, три повтора каждого изображения, сеть отключена.
Ниже Linux/ARM64, Python 3.12, Docker Desktop на Apple Silicon, лимит 2 CPU и 1 ГиБ.
Медиана исключает первый запуск каждого снимка, но включает декодирование и разбор
метаданных. Это время только OCR, без MAX, классификатора работ и Яндекс.Диска.
Полные результаты трёх повторов: [ocr-benchmark-2026-10-14.json](ocr-benchmark-2026-10-14.json).

| Обработчик | Полные метаданные пяти фото | Отдельная дата | Медиана OCR | Пик памяти контейнера |
| --- | --- | --- | --- | --- |
| Прежний Tesseract с повторами | 4/5 | 1/1 | 0,89 с | 111 МиБ |
| Новый PP-OCRv5 с выделением штампа | 5/5 | 1/1 | 0,22 с | 339 МиБ |
| EasyOCR `ru,en`, полный кадр | 0/5 | 1/1 | 8,68 с | достигнут лимит 1 ГиБ |

У EasyOCR в этом ограниченном контейнере были пропуски времени и ошибки цифр;
давление на память также влияет на время. Это результат указанных настроек и этой
выборки, а не универсальный рейтинг библиотек. Сокращения и разделители разбирались
одним и тем же кодом для всех движков; опечатки цифр не исправлялись вручную.

Память измерена через `memory.peak` cgroup и включает процессы и учитываемый
контейнеру файловый кэш. Это не объём одного файла модели и не расход всего сервиса.
Первое фото нового обработчика в этом замере заняло 0,70 с после импорта модулей
(импорт — ещё 0,51 с). На сервере с другой архитектурой/процессором результаты будут
отличаться. Модели занимают около 12 МБ на диске; нейросетевой OCR требует больше RAM,
хотя на этих примерах оказался быстрее прежних проходов по полному кадру.

Дополнительно `test_local_ocr.py` проверяет все пять фотографий в трёх размерах
(1050, 700, 525 пикселей по ширине) с JPEG quality 85: 15 случаев. В этих тестах
резервный Tesseract запрещён, чтобы он не скрывал ошибку новой модели. Дата и время
сравниваются точно, координаты — с допуском 0,000001 градуса.

## Обработка

1. Применяется ориентация EXIF. Фотография для анализа ограничена 4000 пикселями
   по длинной стороне, оригинал не изменяется.
2. Сначала проверяются найденные чёрные прямоугольные плашки. Если данных не хватает,
   проверяются нижние 40% и полный кадр. Маленькие области увеличиваются не более чем
   вдвое; вход детектора ограничен 1280 пикселями, включая очень узкие изображения.
3. Блоки одной физической строки объединяются по координатам. Даты поддерживают
   русские сокращения всех месяцев, латинские похожие символы, английские сокращения
   и отсутствие пробелов: `20апр.2026г.`, `10 нояб.2025`.
4. Пара координат может быть слитной, если обе части имеют полушария:
   `61.1024N72.5793E`. Разбор не заменяет `З` на `3`, не угадывает пропущенные цифры
   и не склеивает отдельные координаты из разных проходов. Неверные диапазоны,
   невозможные даты и противоречивые значения остаются неопределёнными.
5. После полного результата дополнительные проходы не выполняются. При недостатке
   данных или недоступности весов запускается локальный Tesseract с оставшимся
   бюджетом времени. При ошибке резерва сохраняется уже распознанный текст.

## Установка и настройки

Достаточно обновить исходники и выполнить `docker compose up -d --build` из каталога
проекта на сервере. Изменения БД не требуются. Веса скачиваются по HTTPS **при сборке**,
проверяются по закреплённым SHA256 и входят в образ с правами чтения пользователя
сервиса. Модели кэшируются в отдельном слое сборки. Во время обработки используется
только локальный путь: фотография не передаётся в облачный OCR/API, веса не скачиваются.
Телеметрия ONNX Runtime отключается.

Параметры имеют значения по умолчанию, существующий `.env` можно не редактировать:

```dotenv
OCR_BACKEND=paddle
OCR_MODEL_DIR=/opt/ocr-models
OCR_THREADS=2
OCR_TIMEOUT=60
OCR_LANGUAGES=rus+eng
```

Модель загружается лениво один раз на процесс worker, API не загружает её при импорте.
`OCR_THREADS` ограничивает потоки ONNX, OpenCV использует один поток, Tesseract в образе
ограничен двумя потоками. Стандартный worker обрабатывает фотографии последовательно.
`OCR_TIMEOUT` ограничивает запуск следующих попыток; уже идущий синхронный вызов ONNX
завершается самостоятельно. Tesseract получает оставшийся бюджет с таймаутом процесса.

Для работы вне Docker предварительно выполните `python -m app.ocr_models /путь/к/моделям`
и укажите `OCR_MODEL_DIR`. Для возврата к старому движку установите
`OCR_BACKEND=tesseract` и пересоздайте контейнеры. При повреждении/отсутствии нейросетевых
весов резерв включается автоматически, причина записывается в лог worker.

Уже обработанные фотографии и ручные исправления автоматически не пересчитываются.
Новая обработка применяется к новым фотографиям и ещё не проанализированным задачам.
Повторная отправка того же файла по-прежнему подчиняется дедупликации SHA256.

## Повтор проверки

Из `backend/` с установленными dev-зависимостями:

```bash
OCR_MODEL_DIR=/opt/ocr-models uv run pytest -q tests/test_local_ocr.py tests/test_parsers.py tests/test_ocr_dates.py
uv run python scripts/benchmark_ocr.py paddle
uv run python scripts/benchmark_ocr.py tesseract
```

EasyOCR не входит в зависимости сервиса. Для сравнения установите его в отдельную
тестовую среду и заранее скачайте официальные модели. Скрипт запрещает загрузки:

```bash
python scripts/benchmark_ocr.py easyocr --easy-model-dir /путь/к/моделям/easyocr
```
