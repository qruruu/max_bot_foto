# Короткие маркировки и папки микрорайонов

Источник: [таблица работ, лист «Ручные виды — уникальные», столбец F](https://docs.google.com/spreadsheets/d/19aE4mOlMkGM8F5_0Bic_7euY-qgmGRlJnJzHNhugHVs/edit#gid=1922338105).
Используются только короткие маркировки в порядке таблицы:

ПГМ, ПОДХОДЫ, УРНЫ, МУСОР_ГАЗОН, КОЛОДЦЫ, АРМАТУРА, ПЛОЩАДКИ, СЛУЧ_МУСОР,
ПОДМЕТАНИЕ, МОЙКА_УРН, ГРАБЛИ, ГАЗОН, ПОКОС, БРУСЧ_МОЙКА, МЕХ_СНЕГ, ВЫВОЗ_СНЕГА.

Эти названия едины для карточки, фильтров, отчётов, Excel, ответов MAX, страницы обучения
и имён файлов. Внутренние коды сохранившихся категорий остаются стабильными.
Спам — отдельная категория архива, не один из видов работ и не класс для обучения.

## Переход существующих данных

Миграция `0005` объединяет прежние отдельные категории:

| Прежняя категория | Новая маркировка |
| --- | --- |
| Ежедневный осмотр МАФ | ПЛОЩАДКИ |
| Уборка снега на площадках | ПЛОЩАДКИ |
| Летняя уборка площадок | ПЛОЩАДКИ |
| Покос зелёных зон площадок | ПЛОЩАДКИ |
| Уборка упавшего дерева | ГАЗОН |
| Вывоз скошенной травы | ПОКОС |

Остальные категории получают короткие названия. Подтверждения оператора и превью сохраняются
для обучения. Исходные результаты AI, старые снимки обучающей выборки и история моделей не
перезаписываются. Изменения категорий и постановка переноса файлов в очередь записываются в аудит.

Модели с прежними 22 выходами отключаются; формат новой модели — `resnet18-local-v2-short16`.
До обучения и активации модели нового формата новые фотографии требуют выбора вида работы
оператором. Автообучение использует накопленные подтверждённые примеры с обновлёнными категориями,
если выполнены обычные пороги количества и качества. Старые модели не блокируют первый запуск.

## Структура файлов

```text
MAX_PHOTOS/<дата>/<чат>/<микрорайон>/<микрорайон>_<маркировка>_<ID>.<расширение>
MAX_PHOTOS/2026-04-20/Чат_1/12_мкр/12_мкр_УРНЫ_123.jpg
MAX_PHOTOS/СПАМ/<дата>/<чат>/<микрорайон>/Спам_<ID>.<расширение>
```

Если микрорайон не определён, используется папка `МР_НЕ_ОПРЕДЕЛЕН`. После определения или
исправления микрорайона файл переносится в соответствующую папку. Неизвестная дата остаётся
в `ДАТА_НЕ_ОПРЕДЕЛЕНА`.

Миграция ставит сохранённые оригиналы, включая спам, в очередь `SYNC`. Рабочий процесс создаёт
папки, переносит и переименовывает файлы, проверяет хеш, затем обновляет путь в базе. При ошибке
путь остаётся прежним, задача повторяется. Удалённые вручную с Диска оригиналы восстановить из
этой миграции нельзя: для них будет ошибка переноса. Пустые старые папки не удаляются.

## Обновление установленного сервиса

Перед переходом сохраните резервную копию БД: объединённые категории нельзя автоматически
разделить обратно. Остановите процессы старой версии до миграции, чтобы они не продолжали
записывать старые категории или обучать старую модель:

```bash
docker compose build
docker compose stop api worker trainer receiver
docker compose up -d db
docker compose run --rm migrate
docker compose up -d
```

Миграция выполняется в БД; перенос на Диске продолжается в фоне после запуска `worker`.
Ход переноса и ошибки доступны в разделе «Обработка». Исходное ТЗ в `TECHNICAL_SPEC.md`
сохранено как исторический документ; этот каталог заменяет его список работ и схему папок.
