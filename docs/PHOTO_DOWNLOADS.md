# Выбор и скачивание фотографий

Пользователь задаёт фильтры, нажимает «Выбрать все», затем «Скачать».
Выбор действует на всех страницах. Отдельные фотографии можно исключить галочками;
изменение фильтров сбрасывает выбор. При количестве больше десяти пересылка в чат
и задачу скрывается. Выбрать больше 50 фотографий нельзя: после пятидесятой
неотмеченные галочки отключены, отмеченные можно снять. Подсказки о лимите нет.
«Выбрать все» выбирает первые 50 подходящих фото в порядке списка, включая другие
страницы. Сервер повторно проверяет лимит при создании ссылки и перед передачей файлов. Одно фото скачивается как JPEG, несколько — как ZIP64.

## Ограничение нагрузки

- «Выбрать все» читает и возвращает максимум 50 номеров фотографий, без подсчёта
  всей выборки и без загрузки изображений. Браузер хранит только эти номера
  и ссылки; скачивание отправляет конкретные выбранные номера.
- Изображения не загружаются в память страницы. POST создаёт короткую ссылку,
  после чего менеджер загрузок браузера получает поток обычным GET.
- Сервер читает только ID, порциями максимум по 51 (50 и одна запись для проверки лимита). Каждая порция использует отдельную
  короткую транзакцию. Соединение не удерживается во время передачи фотографий.
  Права пользователя проверяются заново перед каждой порцией.
- На каждую БД допускается одна операция массового чтения одновременно через
  транзакционную advisory-блокировку. Каждый SQL-запрос ограничен двумя секундами,
  ожидание блокировки — 250 мс. Занятость и превышение времени возвращают 503.
- Два потока скачивания на общий том `/data`, включая разные организации и процессы
  API: неблокирующие файловые блокировки. Остальные ждут автоматически до пяти
  минут перед авторизацией, без соединения с БД. В процессе API допускается
  максимум 32 запроса этого модуля, включая активные и ожидающие. Переполнение
  или превышение времени ожидания возвращает 503. Закрытие соединения удаляет
  ожидающий запрос и освобождает его место.
- Короткие запросы выбора и состояния также проходят отдельную ограниченную
  очередь. Карта в эти очереди не попадает: её admission и DB-блокировки независимы.
- ZIP не сжимает уже сжатые JPEG. Чтение и передача идут блоками до 64 КиБ,
  каждый поток ограничен 4 МиБ/с (суммарно до 8 МиБ/с), длительность — пять минут.
- Полная копия архива на сервере не создаётся. Только каталог ZIP временно
  записывается на диск: не более 64 МиБ; перед запуском требуется 32 МиБ свободного
  места. Каталог удаляется при завершении, ошибке, обрыве соединения и остановке процесса.
- Маленькие одноразовые ссылки привязаны к организации, пользователю и сессии,
  действуют 15 минут с учётом ожидания и передачи. Хранилище содержит не более
  128 актуальных ссылок. Каждый запрос имеет отдельную ссылку и состояние, поэтому
  запуск второго скачивания не отменяет первое. Завершённые записи очищаются
  после минуты при следующем создании ссылки. Тело запроса ограничено 256 КиБ.
- Nginx для скачивания не буферизует поток и не создаёт временный файл; передаёт
  `X-Accel-Buffering` следующему прокси. Встраивание разрешено только с того же
  origin и только для ответа скачивания, чтобы показать ошибку без ухода со страницы.

Набор выбранных номеров фиксирован. Удаление фото и изменение прав могут изменить
доступность файлов. Исчезнувший файл прерывает загрузку, вместо создания ZIP,
который выглядел бы полным. При достижении защитных лимитов операция прекращается,
сохраняя ресурсы сервиса.

## Проверки

`backend/tests/test_photo_downloads.py` проверяет ZIP и CRC, ZIP64 с 66 000 записями,
ограниченную память при передаче 256 МиБ, ограничения диска, межпроцессную
блокировку, ссылки, SQL-таймаут, два параллельных потока, автоматическое ожидание третьего, независимый проход
карты, отмену ожидания, обрыв и срок загрузки.
`backend/tests/test_photo_selection.py` проверяет реальные SQL-фильтры на SQLite,
права на чаты, ограниченные порции, освобождение соединений и весь путь от ссылки
до JPEG/ZIP, границы 50/51 и повторную проверку изменившейся подборки. PostgreSQL-таймауты проверяются отдельно через имитацию ошибки драйвера.

Тесты интерфейса покрывают фильтры, исключения, переходы между страницами,
выбор максимум 50 фото, невозможность отметить 51-е, освобождение места после
снятия галочки, состояния очереди и передачу загрузки браузеру без Blob.
Нагрузочные испытания на рабочем PostgreSQL и проверка конфигурации запущенного
Nginx выполняются отдельно перед выпуском на сервер.

### Регрессия зависания перед началом передачи

Проверки полного HTTP-пути для 1, 5 и 50 фото проходят через настоящий стек
middleware, создание ссылки, передачу JPEG/ZIP и проверку завершённого состояния.
До исправления запрос на пять фото зависал до вызова обработчика скачивания:
однократная отмена фонового чтения disconnect могла поглощаться внутренней
группой задач `BaseHTTPMiddleware`, а ожидание её завершения блокировало ответ.
Слушатель отключения теперь использует собственный `CancelScope`, отмена которого
сохраняется до выхода из слушателя. Начальное сообщение — «Подготавливаем
скачивание…»: оно не утверждает, что сервер занят чужими загрузками.
