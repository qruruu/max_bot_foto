# Соединения БД и передача файлов

Зависимость `Db` закрывает сессию после выполнения обработчика и сериализации
ответа, до передачи ответа клиенту (`scope="function"`, FastAPI >= 0.121).
То же правило действует для `NewsDb`.

Причина: `FileResponse` с превью и поток оригинала могут передаваться медленно.
Хранить соединение и открытую транзакцию всё это время нельзя: несколько
параллельных передач занимают ограниченный пул, и вход/обычные запросы/healthcheck
ждут его освобождения. Увеличение CPU/RAM или размера пула не устраняет такое
удержание ресурса.

Проверки прав и чтение данных выполняются до возврата ответа. Потоки файлов не
используют сессию БД: превью читает файл, API оригиналов передаёт уже подготовленный
временный файл. Будущие потоковые обработчики должны следовать тому же правилу;
если во время потока требуется БД, нужен отдельный краткий контекст сессии,
закрываемый перед ожиданием клиента.

Сохранение активности сессии остаётся в финализаторе `get_db`: незавершённая
бизнес-транзакция откатывается, вспомогательные метаданные сохраняются отдельно.
Проверки авторизации и изоляция организаций не меняются.

Регрессионная проверка `test_response_connection_lifetime.py` намеренно задерживает
передачу файла при пуле из одного соединения и проверяет, что параллельный health
остаётся доступен. На прежнем времени жизни зависимости соединение остаётся занято.

Для двухъядерного рабочего сервера контейнер обучения ограничен одним ядром
(`trainer.cpus: 1.0`), чтобы вычисления модели не занимали весь CPU. Это замедляет
обучение; ограничение не заменяет контроль пула соединений и не гарантирует
работоспособность при любой нагрузке.
