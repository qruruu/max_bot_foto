# Публикации в разделе «Новости»

Раздел `/news` доступен администратору и операторам с правом `news_view` («Просмотр новостей»).
У операторов оно выключено по умолчанию; администратор включает его в настройках аккаунта.
Без права API списка, статьи и скриншота возвращают `403`; без входа — `401`.
Статьи и скриншоты входят в сборку API, поэтому сохраняются в Git и не требуют отдельной миграции или начального заполнения БД.
Обновление программы не очищает старые публикации. Содержание — общие инструкции к сервису,
без данных конкретной организации. Те же статьи будут доступны на установках этой версии.

## Когда добавлять пост

По просьбе владельца «напиши пост в новости» подготовить публикацию о выполненной задаче
и добавить её в проект. Текст составлять самостоятельно по фактическому результату: что
изменилось, для кого это полезно, где находится функция, как ею пользоваться и какие права нужны.
Не добавлять новость после каждой задачи без такой просьбы. После добавления статьи сообщить,
что на рабочем сервере она появится с обновлением панели; не утверждать, что сервер уже обновлён.

## Как добавить публикацию

1. Добавить объект статьи в `backend/app/news_content/posts.json`. Указать постоянный уникальный `slug`,
   дату публикации `YYYY-MM-DD` в часовом поясе владельца, категорию, заголовок, краткое описание
   и разделы. Список сам сортируется от новых публикаций к старым. У прежних постов сохранять slug,
   чтобы ссылки продолжали работать.
2. Написать понятную инструкцию для пользователя: конкретные названия разделов и кнопок,
   действия по порядку, результат и ограничения. Не включать историю разработки, команды,
   внутренние коды и незавершённые возможности. Если функция зависит от выданных прав, указать это.
3. Проверить функцию в изолированном локальном примере. Снять реальные скриншоты интерфейса,
   показывающие нужные элементы. Сохранить их в `backend/app/news_content/<slug>/` и добавить
   `screenshots` к нужным разделам статьи: имя `file` (PNG/JPG/WebP без пути), содержательный `alt`,
   подпись `caption` и фактические размеры `width` / `height` в пикселях.
   Изображения выдаёт защищённый `/api/news/<slug>/screenshots/<file>`; использовать только тестовые данные,
   без личных сведений, реальных переписок, паролей и токенов. Не использовать временные пути
   `/private/tmp` или локальные адреса в качестве ссылок на иллюстрации.
4. Выполнить `pytest -q tests/test_news.py` в окружении `backend`, `npm test` и `npm run build` в `frontend`. Тест проверяет уникальность ссылок,
   даты, наличие файлов и иллюстраций. Открыть список, статью и увеличение скриншота в браузере;
   проверить возврат, закрытие Esc и обе темы.
5. Показать пользователю результат. Публикация входит в обычное обновление API и `web`;
   не делать commit, push или развёртывание без соответствующего запроса.

Контент отображается как текст React, без HTML из статей, внешних скриптов или встраиваемых страниц.
Для исправления опечатки можно обновить существующий пост; для новой возможности добавить новый.
