# Наблюдение IDS/DLP в закрытом АРМ

Защита работает в режиме наблюдения и предупреждений. Существующие проверки
прав приложения, запреты служебных файлов и ограничение запросов сохраняются.
Разрешённые массовые выгрузки не блокируются автоматически.

## Данные приложений

Чистый ASGI middleware `SecurityTelemetry` установлен внутри маршрутизации
организаций. Существующий код аутентификации добавляет типизированную идентичность
после проверки активной учётной записи и сессии. Владелец, операторы,
администраторы и проверяющие учитываются; переданные клиентом идентификаторы и
заголовки не становятся удостоверением личности. Организация берётся из
разрешённой сервером области. Для проверяющего область может быть неизвестна.
Имена, логины и контакты в новый поток не входят: используются проверенные ID.

Событие `METKA_AUDIT_V1` содержит время, случайный ID события, фиксированную
категорию ресурса, метод, наблюдаемый HTTP-код, результат, число байтов, признаки
измерения/завершения, IP из доверенной конфигурации ASGI proxy и проверенные ID.
Cookie, токены, заголовки, URL/параметры, тела и фотографии не сохраняются.
Новый публичный API мониторинга не добавляется. Health-записи подтверждают,
что оба источника подключены; отсутствие записей и предел чтения показаны в АРМ.

Байты суммируются после успешного ASGI `send` каждой части ответа, без буферизации
или изменения потока. Это байты, переданные приложением в буфер протокольного
сервера, не доказательство получения файла человеком. Частичная выдача и
прерывание отражаются отдельно; оптимизация pathsend отмечается неизмеренной.
[Семантика ASGI send](https://asgi.readthedocs.io/en/latest/specs/www.html#response-body-send-event).

302 на оригинал означает выдачу ссылки Яндекс.Диска. Его последующее скачивание
на стороне Яндекса не измеряется. Отказы 401/403/429, выбор организации и HTTP 200
без подтверждённой сессии не выдаются за успешный вход или утечку.

## Сигналы и ограничения

Закрытый сборщик шифрует события, устраняет повторы и группирует их по проверенной
учётной записи/организации. Для публичного доступа используется отдельная группа
по IP без выдуманного пользователя. Пороги по умолчанию за 10 минут: 100 выдач
изображений/оригиналов, 10 экспортов, 250 МиБ ответа, 100 ссылок на оригиналы,
20 отказов. Пороги задаются секцией `dlp` закрытой конфигурации сборщика, а не
публичным запросом. Каждый сигнал содержит численное основание и не объявляет взлом.

Непосредственное чтение файлов/БД, S3, устройства пользователей и содержание
документов этим модулем не проверяются. Это прикладной контроль выдачи и лёгкая
серверная IDS, не полнофункциональная DLP рабочих станций или сетевой IPS.
Захват root/приложения может позволить обойти или подделать новые события.

## Целостность и порты

Сборщик раз в минуту сравнивает ограниченный набор SSH/sudo/cron/systemd/Nginx,
конфигураций и ключей бэкапа/мониторинга, настроек приложения и кода контроля
с зашифрованной базой. Хранятся хеши и метаданные, содержимое не передаётся в АРМ.
Проверяются изменения, добавления, исчезновение, владелец и небезопасные права;
символические ссылки на секретах не открываются. Новые TCP-listener вне loopback
создают сигнал; наличие listener не доказывает доступность через firewall.

База создаётся явно после проверки развёртывания и не обновляется автоматически.
Она подтверждает сравнение с выбранным состоянием, а не отсутствие старого взлома.
При разрешённых изменениях администратор сначала проверяет причину, затем явно
пересоздаёт базу: `python -m monitor.host_ids baseline --config /etc/metka-monitor/config.json`.
Хеширование ограничено 256 файлами, 8 МиБ на файл и 32 МиБ за проход. Чтение
журналов ограничено последними двумя минутами и 3000 строками на API; при сбое
сбора возможны пропуски, поэтому состояние источника показывается отдельно.

## Проверки и откат

Тесты прикладной телеметрии проверяют потоковую/частичную выдачу, закрытое соединение,
302, поддельные клиентские ID, отсутствие секретных полей, выбор организации и
реальные разрешённые/запрещённые экспорты в отдельной PostgreSQL/PostGIS БД.
Тесты АРМ проверяют группировку, пороги, шифрование, неизменность базы и новые порты.

Развёртывание сохраняет прежние образы двух API и источники сборщика. В рабочие
образы добавляются только файлы этой телеметрии поверх текущих образов. База данных,
миграции, приём/обработка фотографий и бэкапы не перезапускаются. При ошибке проверки
два API возвращаются на прежние образы; конфигурация/сборщик восстанавливаются.
